RinOS SDK

The public SDK contains fixed-width C ABIs, header-only C++20 conveniences, shared driver helpers, and the runtime import contracts used by RinOS applications.

Supported SDK package targets are i686-unknown-rinos and x86_64-unknown-rinos. Application code uses public SDK headers and granted capabilities; it does not include OS-Core headers.

Quick start

Start with <rin/sdk.h> for the common application surface. Include a narrower <rin/...> header when an application only needs one domain. The <rin/cpp/sdk.hpp> wrapper requires C++20 and keeps its C++ types on the caller side of the stable C ABI.

#include <rin/sdk.h>

int main(void) {
    rin_log("Hello from a RinOS application.");
    return 0;
}

The consumer project under examples/consumer is an SDK-only C/C++ compile entry. It compiles one translation unit per public header, then builds the sample translation units without including OS-Core sources. Its consumer guide also documents cross-building and packaging the C examples.

ABI versioning and errors

  • The published package identity is rinos-sdk-v1; the supported target names are recorded in pkg/rinsdk-v1.json.
  • Each versioned request and response sets struct_size = sizeof(record) and its documented version. Reserved fields are zero. A caller checks RinResult before consuming output fields.
  • Keep fixed-width integers and opaque handles at the ABI boundary. Do not pass C++ objects, exceptions, STL containers, compiler bitfields, or pointers to temporary storage across an SDK call.
  • New fields require a versioned ABI change or a reserved-field contract that explicitly permits them. Do not infer compatibility from the compiler, architecture, or the size of an unrelated record.

The top-level SDK ABI declarations are in abi.h. Domain records live beside their APIs; for example, process requests are in base.h and window records are in gui.h.

WinCompat consumers can include <rin/compat/uxtheme_abi.h> for the fixed-width WTA_OPTIONS layout, WTA_NONCLIENT/WTNCA_* values, and the function-pointer type for the SetWindowThemeAttribute export. Its namespaced types avoid collisions with host Windows headers.

Capabilities and handle ownership

Capabilities authorize classes of operations; object handles refer to individual kernel-managed objects. An application requests only the capability bits it needs, and policy may grant fewer or none. A capability bit is not proof that a backing service or device is present.

Handles are opaque, process-scoped values. Treat a handle as a capability, never as an address or object identifier. Duplicating a handle can only narrow its rights. Close each owned handle once with its typed close function or rin_object_close_v1; do not close borrowed handles. If cleanup errors must be reported, call close() explicitly before an RAII wrapper is destroyed. Use try_replace(std::move(next)) when replacing an owned handle and checking close errors matters; on failure both wrappers keep their original handles. Move assignment preserves that same ownership rule but cannot return the close error.

auto created = rin::channel_create();
if (!created) return static_cast<int>(created.code());
rin::unique_handle<RinChannel> endpoint(created.value().first);
/* endpoint closes its owned channel when its scope ends. */

The C++ outcome<T> preserves the ABI result code. Read value() only after checking ok(); output values on failure are not usable results. New code can use try_value(), which returns null on failure.

C++20 strings, buffers, and timeouts

<rin/cpp/sdk.hpp> provides overloads for std::string_view, std::span<T>, and integral std::chrono::duration values. These overloads only build the existing pointer/length and nanosecond C records; the public ABI layout does not change.

#include <array> #include <chrono> #include <cstddef> #include <span> #include <string_view> #include <rin/cpp/sdk.hpp> int main() { std::string_view service = "com.example.echo"; auto channel = rin::service_connect(service); if (auto* value = channel.try_value()) { rin::unique_handle<RinChannel> owned(*value); } std::array<std::byte, 128> input{}; auto sent = rin::socket_send(socket, std::span{input}); auto waited = rin::process_wait(process, std::chrono::milliseconds{250}); }

A string view preserves its byte length, including embedded NULs, and its storage must remain valid for the synchronous call. Span overloads measure bytes, accept empty spans as zero-length slices, and require trivially copyable elements; output buffers require mutable spans. Duration overloads accept integral reps, reject negative values, truncate positive sub-nanosecond values toward zero, and return RIN_ERROR_LIMIT_EXCEEDED when conversion overflows or reaches the ABI's reserved infinite-timeout value. Floating-point durations are intentionally not accepted because their conversion would be lossy.

Processes and IPC

rin_process_spawn_v1 starts an image with an explicit capability mask. A zero mask requests no optional capabilities. Wait on the returned process handle, inspect the exit code only on success, and close the handle on every path.

Channels are bounded and non-blocking. Empty receive and queue-full send return RIN_ERROR_WOULD_BLOCK; wait for readiness before retrying. Inline messages are limited to 64 KiB and handle transfer to 16 handles. Use shared memory for larger payloads. Transferred handles retain their rights and require the source handle's duplicate right.

See ipc.h for the readiness and queue contract, and the C and C++ examples in examples/consumer for spawn, wait, and channel ownership patterns.

File Portal

A File Portal grant represents a user-authorized file object, not a pathname. The privileged chooser resolves the selected object and issues a rights-limited grant. Applications must not manufacture a path from the grant ID or use a grant to bypass their namespace policy.

For a durable grant, pass the grant ID supplied by the trusted portal flow to rin_fs_portal_open_v1. The kernel rechecks the current sandbox identity, object type, rights, expiry, and policy generation, and returns a process-owned file or directory handle. Open with the minimum rights and close the returned handle when finished. The sample file_portal.c reads a regular-file grant using read-only access.

Ephemeral token issue/open and durable-grant syscall records are documented in file_portal.h, file_portal_call.h, and fs.h. Token authentication keys belong to the trusted portal service; ordinary applications must never embed them.

Window and media APIs

The GUI surface in gui.h creates a window, returns versioned events, and presents caller-owned surfaces. Check every result and close both window and surface handles. Window creation does not grant control over other applications' windows.

Media operations are in media.h. They accept an explicit MIME type, source slice, media type, and flags. Query rin_image_get_info_v1 before image decode: v1 returns the first frame as tightly packed ARGB8888 words (format 1, each little-endian output word has numeric value 0xAARRGGBB, stride width * 4). Query rin_audio_get_info_v1 before audio decode: v1 samples are interleaved signed 16-bit little-endian (format 1), with sample rate, channel count, and bytes per frame in the metadata. A clear audio frame-count-known flag means the count is unknown and reported as zero. The caller supplies a bounded output slice; video decode targets a surface. These declarations define the SDK ABI and do not imply that a target decoder service is installed; applications must handle RIN_ERROR_NOT_SUPPORTED and capability denial.

The sample window.c creates a window and waits for one event. examples/consumer/media.c opens a self-contained PNG with the public RIN_MEDIA_TYPE_IMAGE value. The v1 media type numbers are fixed as image=1, audio=2, and video=3 and are compile-time guarded in C11/C++ headers. The sample closes the returned object and handles an unsupported media service explicitly. The media records and functions also have standalone C/C++ consumer coverage in the CMake project.

Driver contract

External drivers use the NDRV v3 public ABI under include/rin/driver/README.md. A driver receives only the capabilities and generation-bound resource leases that the kernel grants. BAR mappings, DMA buffers, IRQs, timers, firmware, and registrations have checked lifetimes; release them before stopping or unloading the module.

Use probe to validate the device and required services, start to publish the active owner, then honor quiesce, stop, and remove ordering. A failed cleanup keeps its lease and driver image for retry. Do not include kernel headers or assume that a PCI match alone grants access to hardware.

Build and package

Configure the standalone header consumer with C and C++ compilers, then build its targets:

cmake -S examples/consumer -B build/consumer
cmake --build build/consumer

From an OS-Core checkout, the same project can be configured with an explicit SDK path:

cmake -S public-base/RinOS-SDK/examples/consumer -B out/sdk-consumer \
  -DRINOS_SDK_ROOT=public-base/RinOS-SDK
cmake --build out/sdk-consumer

The rinosdk_headers_c and rinosdk_headers_cpp object targets compile each public header by itself in C11 and C++20 modes. The rinosdk_example_* targets compile the samples. They intentionally do not link to a host runtime; a RinOS application links the SDK libraries listed in pkg/rinsdk-v1.json with the RinOS target toolchain.

The SDK package manifest lists public-header dependencies as well as runtime libraries. The RinOS release packager copies the selected RinGPU and RinResource public headers into the published SDK include tree, so installed consumers do not need private OS-Core include paths. When building directly from the embedded source checkout, the consumer project resolves those dependency include roots beside the SDK; a separate SDK checkout can pass them with RINOS_RINGPU_INCLUDE_ROOT and RINOS_RINRESOURCE_INCLUDE_ROOT.

C++ consumers use the namespaced RIN_SYS_* syscall constants. Generic legacy SYS_* aliases remain enabled for C; C++ can opt into them with RIN_SDK_ENABLE_LEGACY_SYSCALL_ALIASES when migrating older code.

examples/consumer/build.py uses the packaged public include tree and RinOS compiler to cross-compile, link, validate, and package the hello, process, channel, File Portal, window, and media C examples. It uses the SDK manifest's runtime library inventory and declares the matching runtime package dependencies and least-privilege capabilities. The image-signing identity and application-publisher identity are separate inputs. This build does not demonstrate execution on a RinOS target or availability of the target services.

All API behavior is bounded by the public versioned headers shipped with the selected SDK package. When prose and a versioned declaration disagree, report the mismatch and follow the ABI contract in the header.
